# Журнал изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [4.0.0] — не выпущена

### Ссылки на файл

- Метод API `usage` (GET): где на сайте стоит ссылка на файл или на что-то в папке — `[{table, count}]`.
  Поиск задаёт сайт: `Manager::setUsageFinder(fn(string $url): array, '/uf')` (ядро передаёт
  `System\FileUsage`). Окно подтверждения удаления и окно «Переименовать» предупреждают: «Ссылки на файл есть
  в 2 записях (content, menu). После удаления они перестанут работать.» — окно открывается сразу, предупреждение
  появляется, когда ответит сервер. Без поиска (`setUsageFinder` не вызван) — пустой ответ, предупреждения нет.

### Свой интерфейс (как в редакторе texted)

- Несовместимо: окно больше не использует компоненты админки (`Common/Modal`, `Button`, `TextInput`, `Dropdown`,
  `Tooltip`, `sfAdmin.confirm()`, `sfAdmin.toast()`). Свой слой интерфейса: окна — `<dialog>` (верхний слой
  браузера: открытое последним всегда сверху, в том числе над окнами админки), свои меню, сортировка, подсказка,
  подтверждение удаления и тосты. Стили — обычный CSS `src/assets/styles/file-manager.css` (вместо SCSS в сборке
  админки), подключается шаблоном с версией по времени изменения; токены `--fm-*` берут переменные дизайн-системы
  (`--color-*`) с запасными значениями из Figma, тёмная тема — `data-fm-theme="dark"`. Размеры — px макета.
  Классы разметки — `fm-*` (`fm-card`, `fm-tree-row`, `fm-done`…), окна — `#sf-file-manager`,
  `#sf-file-manager-rename`, `#sf-file-manager-create`, `#sf-file-manager-confirm`.
- Клик по папке открывает её, по файлу — выбирает. Несколько файлов и папки отмечаются галочкой в углу карточки
  (видна при наведении и когда отмечено несколько), Ctrl/⌘+клик, Shift+клик (диапазон), пробел; двойной клик
  или Enter по файлу — «Готово»; стрелки ходят по карточкам, Delete удаляет отмеченное.
- Подсказка кнопки прячется по нажатию и не показывается у открытого меню. Фокус-кольцо — только с клавиатуры;
  поле ввода в фокусе — синей рамкой, как в texted. Esc закрывает только верхнее окно (в окне менеджера —
  сначала меню); клавиши окна не доходят до окна админки под ним.
- При переходе в папку список сразу очищается и показывает загрузку — без прежней папки под новыми крошками.
- В корне кнопка «В корень» отмечена. В дереве стрелка — только у папок с вложенными, пустую не раскрыть.
- Скругление превью карточки — 4 (скругление карточки 12 минус отступ 8): углы выделения и превью идут ровно.
- Телефон и планшет — по размерам Figma (file-window mobile, file-card-mobile, file-tabbar-item, file-modal
  mobile): шапка и поиск с отступом 12, у сортировки без разделителя; строка 56 (превью 40, текст через 8, имя
  и дата через 4), отмеченная — с галочкой слева от превью; нижняя панель 68 (кнопки 52, подпись 11 полужирным
  серым); окна — шторка снизу: крестик 48 в шапке 64, линия 2, заголовок 20, отступы 20 / 16 / 70; тост —
  на всю ширину над нижней панелью. Крошки на телефоне — только родительская и текущая папки.
- Управление на телефоне: долгое нажатие открывает меню, а клик, который браузер присылает, когда палец
  отпускают, больше не закрывает его и не открывает папку; системное меню картинки и выделение текста при долгом
  нажатии (iOS) отключены. Шторка окна поднимается над экранной клавиатурой (`visualViewport`), фокус в поле
  при открытии шторки — без прокрутки (раньше содержимое сдвигалось, пока шторка выезжала). На сенсорном
  экране без наведения в сетке (планшет) галочки видны сразу.
- Тост успеха — зелёный (Figma Feedback/toast success), ошибки — красный, сведения — тёмный.
- Дата изменения — как в макете, год двумя цифрами: `22.11.26 17:32`.
- Сортировка — меню как в макете (выбранный пункт заливкой), а не поле выбора админки. Крестик окна — как в
  макете (тёмный значок на белой кнопке).

### Добавлено

- `window.fileManager.open()` сообщает об отмене: `onCancel` — при любом закрытии без выбора (крестик, Esc,
  подложка, `close()`), и возвращает Promise — выбранные файлы по «Готово» или `null`. На одно открытие ровно
  один ответ; `open()` при открытом окне отменяет прежний вызов. Прежние вызовы с `onSelect` работают как раньше.
- `open({accept})` — какие файлы можно выбрать: массив расширений (`['jpg', 'png']`) или строка как у
  `<input type=file accept>` (`'image/*,.pdf'`). Неподходящие файлы видны, но неактивны (`file-card_disabled`),
  «Готово» их не отдаёт, загрузка через окно — только подходящих (о прочих — сообщение). Без `accept` — как раньше.
- `open({select: true})` — режим выбора без `onSelect` (для Promise). Подключение к редактору texted — в README.
- Сжатие картинок при загрузке (как в редакторе texted): JPEG, PNG и WebP сохраняются в WebP (качество 82),
  большая сторона — не больше 2560 px, прозрачность сохраняется; GIF и прочие — как есть. Без поддержки WebP
  в GD — как есть. Настройка — константы `Manager::COMPRESSED_IMAGES`, `IMAGE_MAX_SIDE`, `IMAGE_QUALITY`
  (переопределяются в наследнике). Несовместимо: загруженный `photo.jpg` сохраняется как `photo.webp`.
- Имя загруженного файла — латиницей (как в texted): «Фото отпуска.JPG» → `foto-otpuska.webp`.
- Статусы загрузки `too_large` (больше `upload_max_filesize`) и `bad_image`.
- Дерево папок подгружается по уровням: `getTree` принимает `depth` (1 — только вложенные папки, 0 или без
  него — всё дерево, как раньше), узел — с `has_children`, `data` — `null`, если уровень не загружен. Окно читает
  корень и раскрытые папки, а не весь каталог `uf` при каждом действии; папки в дереве — по имени.
- Быстрые переходы по папкам: прежний запрос списка отменяется, ответ для другой папки не показывается.
- Массовое удаление при ошибке сообщает, сколько удалено и какой файл не удалён, и обновляет список.
- Окна по макету Figma (file-modal): «Переименовать» — «Старое название» и «Новое название» с подсказками,
  «Создать папку» — подсказка «Латиницей или кириллицей», кнопки «Отменить» и «Применить» / «Создать»
  поровну на всю ширину; тексты подтверждения удаления из макета, «Удалить» — основной кнопкой. Меню папки
  как в макете: «Создать папку», «Загрузить файлы» (в эту папку), «Переименовать», «Копировать путь»,
  «Удалить»; у «Удалить» красный только значок. Сортировка — «По названию», «Дата изменения», «Вес файла»,
  текстом без поля. Сетка — 4 колонки и при полосе прокрутки. Поиск на телефоне — «Название файла».
- Скачивание отдаёт файл потоком (без чтения в память), с `Content-Length` и именем в UTF-8 (`filename*`).
- Размер файла — с одним знаком после запятой до 10 (1,5 мб) вместо отброшенной дробной части.

### Безопасность

- Несовместимо: изменяющие действия API (`delete`, `createDir`, `rename`, `upload`) — только POST (иначе 405)
  и с CSRF-токеном сессии (`X-CSRF-Token`; иначе 403), если `Manager` получил проверку третьим аргументом
  конструктора (`$csrfFn`, ядро передаёт `Csrf::isValid()`). Раньше они выполнялись и по GET: картинка
  `<img src="/admin/fm?method=rename&path=&name=x">` в тексте страницы переименовывала или удаляла папки `uf`,
  когда администратор открывал страницу. `file-manager.js` отправляет токен из `meta[name="csrf-token"]`.
  Свои вызовы API с изменением файлов переведите на POST с этим заголовком.
- Путь (`path`) разбирается одной проверкой для всех методов: начинается с `/`, сегменты без `.`, `..`, `\`
  и нулевого байта, не проходит через символические ссылки и не выходит из корня (`realpath`). Раньше `path=_old`
  открывал соседнюю папку `public/uf_old`. Корень нельзя удалить и переименовать (`rename&path=` переименовывал
  весь `uf`) — 400.
- Удаление папки не заходит в символические ссылки внутри неё (удаляется сама ссылка).
- Загрузка не перезаписывает файл с тем же именем: свободное имя `photo-2.webp`, занятие атомарное.
  GIF, AVIF, BMP, ICO, TIFF, HEIC с HTML, скриптом или PHP внутри не принимаются (статус `bad_image`).
- Ответы API — с `Cache-Control: no-store`.

### Исправлено

- Подтверждение удаления открывалось под окном менеджера, а окно менеджера становилось недоступным —
  слои окон исправлены в `Common/Modal` ядра (нужна версия ядра с этим исправлением).
- Меню неактивного файла: «Удалить» удаляет этот файл, а не выбранные.

### Изменено

- Несовместимо: API `/admin/fm` отвечает конвертом `JsonEnvelopeResponse` ядра: `{"error": {"code": 0, "message": ""}, ...}`;
  списки (`getTree`, `getFileList`, статусы `upload`) — в `items`, пустой ответ изменяющих методов — только `error`.
  Вместо `success` и кодов вида `not_authenticated` — HTTP-статус (401 не вошёл, 403 запрещено или нет прав
  на запись, 404 не найдено, 409 имя занято, 413 большой файл, 422 недопустимое имя) и `error.message` на русском.
  `file-manager.js` разбирает конвертом.
- Новый дизайн админки Simflex CMS 4.0 (Figma SimflexCMS, страница Way-File): окно `file-window` на компонентах
  Layout ядра (`Common/Modal`, `Button`, `TextInput`, `Dropdown`, `Tooltip`) — шапка с крошками, дерево папок,
  поиск и сортировка, сетка карточек (на планшете и телефоне — список и нижняя панель), сведения о файле, «Готово»;
  меню файла и папки по правому клику или долгому нажатию; окна «Переименовать», «Новая папка»; удаление —
  подтверждением админки. Светлая и тёмная тема.
- Стили — `src/assets/styles/file-manager.scss` на токенах ядра, собираются со стилями админки
  (`LayoutManager::useStyle()`); иконки — свой спрайт `src/assets/img/icons.svg` (набор `file-icon`).
- JS — ES-модуль `src/assets/js/file-manager.js` без jQuery: `window.fileManager.open({multiple, onSelect})`,
  `close()`; `init(callback)` оставлен для прежних вызовов. Изменяющие запросы — POST.
- Шаблон `src/tpl/index.tpl` получает переменные `$fileManagerApi`, `$fileManagerRoot`, `$fileManagerAssets`,
  `$theme` вместо глобальных `fileManager.apiBase`, `rootDir`, `assetsDir`.
- API: в `getFileList` — `bytes` и `mtime` (сортировка), картинки — также jpeg, gif, avif; скрытые файлы и папки
  (с точки) не показываются; размер картинки, который не читается, — пустой вместо ошибки.

### Удалено

- `src/assets/css/*` (`styles.css`, `styles.min.css`, `.map`, `styles.scss`), `src/assets/js/app.js`, `app.min.js`,
  картинки-заглушки `src/assets/img/file-img-*`, пример `bootstrap.php`.
